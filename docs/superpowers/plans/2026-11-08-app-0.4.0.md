# Application 0.4.0 — Implementation Plan

> **For agentic workers:** Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** « fait » qui agit sur les données, inventaire élargi à l'entretien et à l'hygiène, produits à compléter dans Décider, mise à jour de l'application depuis l'application.

**Architecture:** Tout le sens reste côté serveur. Les cartes portent une action `done` (outil `app_*` + arguments) que l'application exécute par le passe-plat existant. Les zones et les questions de complétion viennent du module. La tête sert l'APK de la release déployée.

**Tech Stack:** Rust (tête axum, tentacule alimentation rmcp/rusqlite), Android Kotlin/Compose (PackageInstaller), script de déploiement bash.

**Spec:** `docs/superpowers/specs/2026-11-08-app-0.4.0-design.md` (+ `2026-11-08-app-mobile-design.md`).

## Global Constraints

- `CLAUDE.md`, `CONTRIBUTING.md` ; une branche `feat/<sujet>` par tâche ou groupe de tâches liées, PR vers `develop`, worktree `.worktrees/<branche>`.
- L'application ne parle qu'au serveur (jamais à GitHub ni à un tiers).
- Outils exécutables depuis l'application : uniquement `app_*`, via `POST /app/v1/tools/{module}/{tool}`.
- Gestes et annulation 4 s comme dans les versions précédentes ; bouton visible pour chaque geste ; système de mouvement `ui/theme/Motion.kt`.
- Rust : `cargo test -p tete -p kairos-alimentation` vert ; Android : `./gradlew --no-daemon testDebugUnitTest assembleDebug` vert.

### Contrat : action `done` d'une carte

Champ optionnel d'une carte `cards` :

```json
"done": {"tool": "app_meal_done", "args": {"day": "2026-11-12", "slot": "soir"},
         "choices": {"label": "Portions mangées", "key": "portions", "options": [1, 2, 3], "default": 1}}
```

`tool` commence par `app_` (sinon la tête retire `done`) ; `args` objet JSON borné ; `choices` optionnel (l'application demande la valeur et l'ajoute à `args` sous `key`). Résultat de l'outil : `{"message"}` affiché en snackbar.

### Contrat : APK servi par la tête

- `GET /app/v1/app` → `{"version": "X.Y.Z", "size": n}` ou 404 si aucun APK déposé.
- `GET /app/v1/app.apk` → le fichier (`application/vnd.android.package-archive`), authentifié comme le reste.
- Emplacement côté serveur : `TETE_APP_APK_DIR` (un seul fichier `kairos-vX.Y.Z.apk`, version lue dans le nom).

## Review Focus

1. Double « fait » (double tap, réseau qui renvoie) sur un repas : noté une seule fois, stock décompté une seule fois (Task 2 : `meal_done_twice_refused`).
2. « Fait » sur un reste sans plat en stock : message clair, rien de négatif (Task 2 : `leftover_done_without_dish`).
3. Carte `done` dont l'outil n'est pas `app_*` : action retirée par la tête, jamais exécutée (Task 1 : `done_with_non_app_tool_is_dropped`).
4. APK plus ancien que la version installée : pas de proposition de mise à jour (Task 6 : `no_update_when_server_older`).
5. Produit déjà complété par la conversation entre-temps : la carte de complétion disparaît, la réponse ne régresse pas la fiche (Task 4 : `completion_skips_already_known`).
